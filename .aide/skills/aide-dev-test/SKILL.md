# aide-dev-test: テスト実行・証跡収集・レポート生成

テスト仕様書（単体/結合）に基づきテストを実行し、証跡を自動収集してレポートを生成する。**証跡ファイル名はテストケースID（TC-UT-* / TC-IT-*）と一致させる。**

## 手順

### 1. 事前読み込み
プロファイルの作業フォルダから、対象機能のテスト仕様書・対応する設計書・ソース・テストコードを読む。テストツール設定（プロジェクトの技術スタック記載）を確認。未指定時のデフォルト: テストFW=プロジェクト依存、CLI証跡=`ansi2html`、画面=`Playwright`。

### 2. テスト種別・モードの確認
`unit` / `integration` / `both`、対象機能、`full`（全件）/`failed`（前回失敗分）を確認する。

### 3. テスト実行と証跡収集
- **CLI/API**: 実行ログをキャプチャし `ansi2html` でHTML化 → `<TC-ID>.html`
- **画面（Playwright）**: 手順の各ステップでスクリーンショット → `<TC-ID>-<ステップ>.png`、ログも `<TC-ID>.html`
- 証跡は作業フォルダのテストフェーズの証跡領域（単体/結合で分離）に配置。ファイル名はTC-IDと一致

### 4. 証跡ドキュメントとレポート
- **証跡一覧**: 各TCの結果（PASS/FAIL）と証跡ファイルへのリンク、失敗詳細（期待/実際/原因/対応）
- **サマリレポート**: 総数・合格率・機能別結果・不合格一覧・品質判定（合格基準: 全件合格／重大度高の不合格0件 等）
- テスト結果は改ざんしない（失敗は正直に記録）

### 5. 不合格時・完了後
- 不合格は課題（`I-XXX`）に起票し、仕様不備か実装不備かを切り分け
- トレーサビリティオプション時はマトリクスのテスト結果列を更新
- `aide-review` を起動し、V字対応ペルソナでテスト仕様・結果を上流成果物と照合レビュー（単体⇔`detail-design-reviewer` 等）

## 注意事項
- TC-IDと証跡ファイル名を必ず一致させる
- 証跡は上書きせず実行日でフォルダ分け、または Git で履歴管理（大量SSは .gitignore 推奨）
- 監査オプション時は実行記録を監査証跡に残す
