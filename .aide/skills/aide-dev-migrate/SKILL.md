# aide-dev-migrate: 依存移行・アップデート

依存やランタイムのバージョンアップ・移行を安全に行う。CVE脆弱性チェックを含む。

## 手順

### 1. 移行対象の確認
`security`（CVE対応）/ `update`（バージョンアップ）/ `migrate`（フレームワーク移行）と、対象（パッケージ名 / `all`）を確認する。

### 2. 事前読み込み
パッケージ管理ファイル（package.json / requirements.txt / pyproject.toml / go.mod / Cargo.toml 等）と、対象を使用するソースを特定する。

### 3. 並列分析（Claude Code はサブエージェント）
- **CVEスキャン**: `npm audit` / `pip-audit` / `govulncheck` / `trivy` 等。未導入時は WebSearch で NVD / GitHub Advisory を参照。重大度・修正バージョン・影響範囲を表化
- **破壊的変更分析**: CHANGELOG / Migration Guide から破壊的変更を列挙
- **影響範囲特定**: 対象を import/require するファイルを grep で全特定
- **テスト影響分析**: 影響を受けるテストを特定

### 4. 移行計画の生成
作業フォルダの管理領域に移行計画を出力する：CVEサマリ（Critical/High/…件数と対応必須一覧）、影響範囲、段階的移行手順（セキュリティ修正→マイナー→メジャー）、リスクと対策、**ロールバック手順**。

### 5. 承認後の移行実行
承認を得て段階実行する：移行ブランチ作成 → 依存更新 → 破壊的変更対応（`aide-dev-code` 連携）→ `aide-dev-test` で全テスト → CVE再スキャンで解消確認。

### 6. 結果の記録とレビュー
- 課題管理に移行結果を記録、技術スタックのバージョン情報を更新
- `aide-review`（`security-reviewer`）で残存脆弱性・変更の妥当性をレビュー

## 注意事項
- Critical/High のCVEは即時対応を推奨
- メジャーアップは必ず段階的に。移行はブランチで行い main へ直接 push しない
- ロールバック手順を事前確認してから開始する
- 定期実行（スプリント開始・リリース前・CVEアラート時）に `security` を推奨
