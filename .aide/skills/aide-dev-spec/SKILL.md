# aide-dev-spec: フェーズ別仕様作成（ウォーターフォール×SDD）

新規開発の各フェーズの成果物を、前フェーズへの準拠を保ちながら作成する。ハーネスエンジニアリング（インプット精度向上＋アウトプットの徹底チェック）を実現する。

## 手順

### 1. 対象フェーズの特定
プロファイル・`aide-journey` の現在地から対象フェーズを判定する：要件 / 基本設計 / 詳細設計 / 実装計画。フェーズフォルダが無ければ選択式で生成（オンデマンド）。

### 2. 前フェーズ成果物の読み込み（準拠の基準）
対象フェーズの上流成果物を読む。**この上流が「正」であり、本フェーズはそれに準拠する。**
- 基本設計 → 要件書
- 詳細設計 → 基本設計書
- 実装計画 → 詳細設計書

### 3. 成果物の作成（カタログ雛形ベース）
[成果物カタログ](../../templates/deliverables-catalog.md)で選択された当該フェーズの成果物について、雛形（`.aide-templates/` 優先）に沿って内容を対話で固める。
- 上流の各項目が本フェーズに展開されているかを確認しながら書く（漏れ・独自判断を作らない）
- 要件には `R-XXX` を付番（トレーサビリティオプション時はマトリクスも更新）
- 管理系（工数・スケジュール・担当）は成果物に混ぜず管理領域へ

### 4. 前フェーズ準拠チェック（製造まで徹底）
作成後、**上流成果物との整合**を自己点検する：上流の全項目がカバーされているか、矛盾・逸脱がないか。逸脱を見つけたら是正案を提示する。

### 5. レビュー起動（V字対応ペルソナ）
完了時に `aide-review` を起動し、対応ペルソナでレビューする：
- 要件 → `requirements-reviewer`（⇔運用テスト）
- 基本設計 → `basic-design-reviewer`（⇔結合・システムテスト）
- 詳細設計／実装計画 → `detail-design-reviewer`（⇔単体テスト）

### 6. 次フェーズへの橋渡し
指摘対応後、`aide-journey` で次フェーズを案内する。実装は `aide-dev-code`、テスト仕様は `aide-dev-testspec` へ。

## 注意事項
- 仕様が唯一の正。実装・テストはここで固めた仕様から導出する
- 仕様外の判断が必要になったら、決め打ちせずユーザーに確認し、`aide-sync` で仕様へ反映する
- 決定はブレスト結論としてフェーズの index.md に記録する
