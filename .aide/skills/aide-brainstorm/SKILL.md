# aide-brainstorm: ブレスト → 成果物作成・更新

対話で検討し、成果物に落とす汎用ブレスト。フェーズに応じた分割軸で整理し、成果物を段階的に更新する。

## 手順

### 1. テーマ・対象成果物の確認
- テーマ・背景・目的・制約を確認
- プロファイル（セグメント・有効フェーズ）と[成果物カタログ](../../templates/deliverables-catalog.md)から、対象となる成果物と雛形（`.aide-templates/` 優先）を特定する
- 作業フォルダ未設定なら確認（[作業フォルダルール](../../rules.md#作業フォルダルール)）

### 2. 現在地の確認（ガードレール）
`aide-journey` の現在地・前フェーズ成果物の有無を確認する。前フェーズが薄い／未着手のまま先へ進もうとする場合は、**警告と選択肢を提示**して判断を仰ぐ（勝手にスキップしない）。

### 3. 分割軸での検討
フェーズに応じた軸（要件: 機能/非機能/制約、設計: 画面/データ/処理/連携 等）で論点を分割し、対話で1つずつ詰める。決め打ちせず選択肢を出す。

### 4. 成果物への反映
雛形に沿って成果物を段階的に更新する。
- 要件には `R-XXX` を付番（トレーサビリティオプション時はマトリクス更新）
- 管理系（工数・スケジュール・担当）は混ぜず管理領域へ
- 検討の結論を該当フェーズの `index.md`（検討履歴）に日付つきで要約記録

### 5. レビューと次アクション
- 完了時に `aide-review` で対応ペルソナのレビューを案内・起動
- `aide-journey` で次フェーズを案内

## 注意事項
- 思考過程（ブレスト）を必ず履歴として残す（結論だけでなく検討経緯）
- 大きな方針変更・決定は `aide-sync` の反映フロー（OKゲート）を通す
- 成果物カタログにない成果物を作る場合は、カタログ調整（`aide-init` 手順2-2 / `.aide-templates/`）を案内
