# aide-dev-testspec: テスト仕様書作成

設計書・要件書・ソースからテスト仕様書を作成する。単体／結合を分離し、仕様カバレッジを示す。

## テストケースID体系
| 種別 | ID形式 | 例 |
|---|---|---|
| 単体テスト | `TC-UT-{機能略称}-{連番}` | TC-UT-AUTH-001 |
| 結合テスト | `TC-IT-{機能略称}-{連番}` | TC-IT-AUTH-001 |

## 手順

### 1. 事前読み込みとV字対応
プロファイルの作業フォルダから、テストの正となる上流仕様を読む（V字対応）：
- 単体テスト → 詳細設計書（製造計画書のテストケースも入力に）
- 結合・システムテスト → 基本設計書
- 運用テスト → 要件書

対象機能のソース・既存テストがあれば読む。

### 2. テスト種別の確認
`unit` / `integration` / `both` と対象機能（機能略称）を確認する。

### 3. 並列テストケース抽出
並列で抽出する（Claude Code はサブエージェント）：
- 単体・正常系 / 単体・異常系&境界値 / 結合・機能間連携&E2E / 非機能観点 / 仕様カバレッジ分析
- 画面操作を伴うテストは Playwright 前提で手順にUI操作を明記。CLI/APIテストと種別を区別

### 4. テスト仕様書の出力
作業フォルダの該当テストフェーズに、単体・結合を分離して出力する。各テストケースに「ID／分類／前提／手順／期待結果／優先度／テスト種別（CLI/Playwright）」を記載。

仕様カバレッジ表を付ける（どの仕様がどのテストでカバーされるか、単体＋結合の統合カバレッジ、未カバー仕様の明示）。

### 5. 完了後
- 未カバー仕様があれば報告し対応を確認
- トレーサビリティオプション時はマトリクスにテスト仕様列（TC-UT/IT）を更新
- `aide-review` で対応ペルソナ（詳細設計⇔`detail-design-reviewer` 等）にV字照合レビューを依頼

## 注意事項
- テストケースは仕様から導出する（コードから逆算しない）
- 単体/結合の境界（関数単位 vs コンポーネント間連携）を明確にする
- テストコード生成は `aide-dev-code`、実行・証跡は `aide-dev-test`
