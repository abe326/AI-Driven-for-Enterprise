# aide-advisor: アドバイザー（自由モードの入口）

何も指定せず作業指示が来たとき、または「何をすればいい？」と迷ったとき、決め打ちせずに現在地を分析し、必要な確認を挟んだ上で、**適切なスキルを提案し、承認を得てから実行する（いきなり実行しない）**。[rules.md](../../rules.md) の「自由モード」のデフォルト手順を実行する。

> このスキル自体が裏で自律的に常駐起動するわけではない。自由モードの自動性は rules.md（常時ロード）が担保し、本スキルは「明示的に叩ける相談役の入口」＋「詳細なルーティング表」を提供する。

## 手順

### 1. 不明確さの判定

指示の **目的・対象・成果物** が揃っているかを判定する。

- **不明確**（目的が曖昧、対象が特定できない、成果物が定まらない）→ 決め打ちせず、一度ブレストを提案する:
  > ご指示の意図を固めるために、一度ブレストしませんか？（`aide-brainstorm`）
  > このまま進める場合は、対象と期待する成果物を教えてください。
- **明確** → 次へ進む

ユーザーが「ブレストする」と答えたら `aide-brainstorm` を実行する。「このまま進める」と答えたら不足情報を1〜2点だけ確認して次へ。

**ファイル先置きフローの検知**: 「対応を検討して」「これ見て」のように、利用者が作業フォルダ内にファイル（問い合わせ・障害メモ・要件メモ等）を先に作成して依頼してきた場合は、**作業フォルダ内の該当ファイルを読んで対象・意図を把握する**。未起票なら後続スキルで T-XXX/I-XXX 起票につなぐ。対象ファイルが複数で特定できないときのみ確認する。

### 2. 作業フォルダの確認

成果物を生成しうる指示の場合、プロファイル（CLAUDE.md の「## aideプロファイル」）に作業フォルダがあるか確認する。

- **未設定** → 出力先を確認する。確認なしに作業フォルダ外へファイルを作らない。確定したらプロファイルへの記録を提案する（または `aide-init` を案内）
- **設定済み** → そのフォルダを使う

### 3. 決定・変更の検知

会話の中で決定事項・仕様変更・新事実が生じていれば、[反映フロー](../../rules.md#会話ドキュメント反映フロー)に従い反映計画を提示する（実施は `aide-sync`、OK ゲートを必ず通す）。

### 4. スキルの提案と実行（いきなり実行しない）

下表から適切なスキルを選び、**提案して承認を得てから実行する**。判定はプロファイルのセグメントを優先し、無ければ指示内容・現在地から推定する。

> 例: 「〜のため **`aide-ops-investigate`** を実行するのが適切です。進めてよいですか？」
> → ユーザーが承認したら実行。承認が得られるまでスキルを起動しない。

**迷っている場合（相談役モード）**は、現在地（プロファイル・`aide-journey` の進行状況・成果物の有無）を分析し、候補を **1〜3個・理由つき**で提示して選ばせる:

> | # | おすすめ | 理由 |
> |---|---|---|
> | 1 | `aide-dev-spec`（基本設計） | 要件は完了済み。次は基本設計フェーズ |
> | 2 | `aide-review`（要件レビュー） | 先に要件をペルソナレビューしておくと安全 |
>
> どれにしますか？（番号 or スキル名）

| ユーザーの意図 | 実行スキル |
|---|---|
| 初期化したい / 伴走してほしい | `aide-init` |
| 要件・設計などを整理したい / 何を作るか決めたい | `aide-brainstorm` |
| KPI・ゴールを決めたい（pm） | `aide-pm-charter` |
| スケジュール・課題・メンバを管理したい（pm） | `aide-pm-manage` |
| 打合せメモを議事録化したい | `aide-pm-meeting` |
| 見積もりを出したい | `aide-pm-estimate` |
| 資料・スライドを作りたい | `aide-pm-slide` |
| 製品の不具合・設定を解決したい（product） | `aide-product-resolve` |
| 運用課題・設定作業を記録したい（product） | `aide-product-task` |
| 仕様書（要件/設計/実装計画）を作りたい（dev） | `aide-dev-spec` |
| コードを書きたい / 実装したい（dev） | `aide-dev-code` |
| テスト仕様を作りたい（dev） | `aide-dev-testspec` |
| テストを実行・証跡を残したい（dev） | `aide-dev-test` |
| 依存更新・脆弱性チェック（dev） | `aide-dev-migrate` |
| 問い合わせを受け付けたい（ops） | `aide-ops-inquiry` |
| 課題に対応したい（ops） | `aide-ops-issue` |
| 障害に対応したい（ops） | `aide-ops-incident` |
| 調査したい（ops） | `aide-ops-investigate` |
| 修正したい（ops） | `aide-ops-fix` |
| レビューしたい | `aide-review` |
| 図を描きたい | `aide-diagram` |
| 成果物を文書化（HTML/PDF/docx）したい | `aide-export` |
| 会話内容をドキュメントへ反映したい | `aide-sync` |

## 注意事項

- **いきなり実行しない**: スキルを起動する前に必ず提案し、ユーザーの承認を得る（相談役に徹する）
- **不可逆・外向き操作は各スキル内の承認ゲートも通す**（二重の Human-in-the-Loop）
- 該当スキルが無ければ、通常の作業として進めつつ、決定が生まれたら記録を案内する
- このスキルは現在地分析・提案・起動の橋渡しに徹し、実作業は各スキルに委ねる（軽量に保つ）
