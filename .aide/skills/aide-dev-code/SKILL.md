# aide-dev-code: 仕様駆動コード作成

仕様を正としてコードを作成・修正する。実装前に必ずユーザーの承認を取る。

## 手順

### 1. 事前読み込み（最小）
プロファイルの作業フォルダから、対象機能の **詳細設計書** と **製造計画書**（実装の正）を読む。課題管理で対象タスクを特定。修正時は対象の既存ソースを読む。関連しない履歴は読まない。

仕様が曖昧・不足・矛盾している場合は**実装せず報告**し、`aide-dev-spec`/`aide-sync` で補完してから進む。

### 2. 実装前の確認（必須・承認ゲート）
製造計画書を基に、以下を提示して承認を得る。**「OK」が出るまで実装に着手しない。**
- 準拠する仕様 / 対象ファイル / 処理フロー（正常系・異常系）/ 入出力 / 依存関係 / 実装方針
- 仕様に記載がなく判断が必要な点（あれば仕様補完を提案）

### 3. 実装（並列）
承認後、並列で進める（Claude Code はサブエージェント）：
- **実装**: 仕様に準拠してコード生成（スケルトン→ロジック→エッジケース）
- **仕様準拠チェック**: 生成コードと仕様を照合し差異を報告
- **既存テスト実行**: あればテストを実行しパスを確認

### 4. Spec-Anchored（仕様同期チェック）
実装後、コードと仕様の差異を検出する（追加実装／仕様変更／仕様未実装／暗黙の依存追加）。差異があれば選択肢を提示する：
1. **仕様を更新**（`aide-sync` で反映計画→OK→反映。ブレスト結論にも記録）
2. **コードを仕様に合わせる**
3. **差異を課題化**（`I-XXX` 起票）して進める

### 5. 規約・トレーサビリティ
- CLAUDE.md のコーディング規約に従う。1PR=1タスク。Conventional Commits（関連仕様を明記）
- トレーサビリティオプション有効時は `traceability-matrix.md` のコードファイル列を更新し、変更影響を提示
- 監査オプション有効時は実行記録を監査証跡に残す

### 6. 完了後レビュー
`aide-review` を起動し、`code-reviewer`（＋必要に応じ `security-reviewer`）で仕様準拠・品質・セキュリティをレビューする。

## 注意事項
- 仕様にない機能を独自判断で追加しない（必要なら仕様へ反映）
- セキュリティに関わるコードは特に慎重に。`.env`・認証情報をコードに含めない
