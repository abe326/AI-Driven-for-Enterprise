# aide-ops-incident: 障害対応受付

既存運用の障害を受け付け、緊急対応を整理・記録する。

## 手順

### 1. 受付（緊急）
発生時刻・事象・影響範囲・検知経路・暫定状況を素早く受け取る。優先度は原則「高」。**利用者が `障害-incident/` 等に先にファイルを作成して依頼した場合は、そのファイルを正として読む。** 未起票なら本手順で T-XXX を起票し、その内容を障害報告書に取り込む（重複作成しない）。

### 2. 一次対応の整理
- 影響範囲（ユーザー・機能・データ）の特定
- 暫定対応（回避策・縮退運転）の有無と要否
- エスカレーション要否

### 3. 起票と記録
T-XXX を採番し、タスク管理に起票（種別=障害）。`障害-incident/T-XXX-件名/` に**障害報告書**を作成する（`ops-incident` 雛形）：発生〜検知〜一次対応の時系列、影響、暫定対応。

### 4. 調査・恒久対応へ
原因調査は `aide-ops-investigate`、恒久修正は `aide-ops-fix`。原因分析（`ops-rca`）・再発防止策（`ops-prevention`）を後続で作成する。

### 5. レビュー
障害報告書は `aide-review`（`document-reviewer`）で正確性・追跡性を点検できる。

## 注意事項
- 緊急時はまず一次対応と影響把握を優先し、記録は時系列で残す
- 本番操作は不可逆性・ロールバックを確認し、承認を得てから実施を案内する
