# aide-journey: 伴走モデル

選択されたセグメント・フェーズに沿って伴走タスクを生成し、タスク順での進行を支援する。先走り・出戻りを検知して指摘する。[rules.md](../../rules.md#伴走モデルaide-journey) の伴走モデルを実行する。

## 手順

### 1. プロファイルの読み込み

CLAUDE.md の「## aideプロファイル」からセグメント・作業フォルダ・有効フェーズを読む。無ければ `aide-init` を案内する。

### 2. 伴走タスクの生成・更新

セグメントと有効フェーズから伴走タスクを導出し、作業フォルダ内の管理ファイル（`00_pm-管理/` の課題/タスク管理、または `journey-伴走.md`）に記録する。

- 各タスクに **前提（依存）** と **完了条件** を明記する
- 既に成果物が存在するフェーズは「完了/進行中」として状態を反映する
- セグメント別の標準フロー例:
  - `dev`: 要件 → 基本設計 → 詳細設計／実装計画 → 実装 → 単体 → 結合 → システム → 運用テスト
  - `pm`: 憲章(KPI/ゴール) → スケジュール → 課題/メンバ管理 → 定期レビュー
  - `product`: 課題受付 → 調査(バージョン指定検索) → 設定作業 → 記録
  - `ops`: 受付(問い合わせ/課題/障害) → 調査 → 修正 → クローズ

### 3. 現在地と次アクションの提示

> **現在地**: 基本設計（進行中）
> **次アクション**:
> 1. 設計書 §4 のデータモデルを確定（`aide-brainstorm`）
> 2. 確定後、`aide-review` で基本設計レビュー
>
> （詳細設計・実装はこの後です）

### 4. 先走り・出戻りの検知と指摘

ユーザーの指示が現在地より先のタスクや、確定済み事項の蒸し返しに該当する場合は、進める前に指摘する。

- **先走り**（前提未充足）:
  > **先走りの可能性があります**
  > 「実装」の前に「詳細設計」が未完了です（依存: 詳細設計）。
  > 先に詳細設計を進めますか？ それでも実装に進みますか？
- **出戻り**（確定事項の蒸し返し）:
  > この点は <日付> のブレストで確定済みです（結論: …）。
  > 変更する場合は `aide-brainstorm` で検討履歴を残すことを推奨します。

指摘した上で、最終判断はユーザーに委ねる（Human-in-the-Loop）。強制はしない。

### 5. フェーズ完了時のレビュー連携

フェーズの成果物が概ね完成したら、`aide-review` による該当ペルソナの自動レビューを案内・起動する。次フェーズへの移行を提示する。

## 注意事項

- 進行は支援であり強制ではない。先走りも、ユーザーが意図していれば尊重する
- タスク状態は管理ファイルで一元管理し、成果物（要件書等）には混ぜない
- 新しいフェーズが必要になったら、選択肢を出してフォルダ追加生成を提案する（`aide-init` のオンデマンド生成）
