# aide-review: ペルソナ別自動レビュー

対象に応じたペルソナエージェント（[.aide/agents/](../../agents/)）を起動し、独立した観点でレビューさせて指摘事項をまとめる。[rules.md](../../rules.md#レビューエージェント起動規約) のレビュー規約を実行する。

## 手順

### 1. レビュー対象とペルソナの特定

完了した作業・指定された対象から、起動するペルソナを選ぶ。プロファイルのセグメントと有効フェーズを参考にする。

| 対象 | 起動ペルソナ | V字対応 |
|---|---|---|
| 要件書 | `requirements-reviewer` | ⇔運用テスト |
| 基本設計書 | `basic-design-reviewer` | ⇔結合・システムテスト |
| 詳細設計書 / 製造計画書 | `detail-design-reviewer` | ⇔単体テスト |
| 実装コード | `code-reviewer`（+ `security-reviewer`） | — |
| 既存運用ドキュメント・対応記録 | `document-reviewer` | — |
| 既存システムの修正ソース | `source-reviewer` | — |
| PM成果物（憲章/スケジュール/課題/体制） | `pm-reviewer` | — |
| 製品設定作業・手順 | `product-setting-reviewer` | — |

複数該当する場合は複数起動してよい（例: コード = code + security）。

### 2. ペルソナエージェントの起動

- **Claude Code**: 各ペルソナを**独立したサブエージェント**として起動する（`.claude/agents/<name>` を Agent/Task で起動）。独立コンテキストで客観性を保つ。複数ペルソナは並列起動できる
- **その他のツール（Copilot/Codex 等）**: ネイティブのサブエージェントが無い場合、`.aide/agents/<name>.md` の定義を読み込み、その観点で単一コンテキストでレビューする（フォールバック）

各ペルソナには対象ファイルのパスと、V字照合する場合は対応フェーズの成果物パスを渡す。

### 3. V字照合（新規開発のテストフェーズ）

テストフェーズのレビューでは、対応する上流成果物と照合する。

- 要件定義 ⇔ 運用テスト（`requirements-reviewer`）
- 基本設計 ⇔ 結合・システムテスト（`basic-design-reviewer`）
- 詳細設計（実装計画） ⇔ 単体テスト（`detail-design-reviewer`）

テスト仕様書・テスト結果が上流成果物を網羅・検証しているか、逸脱がないかを点検させる。

### 4. 指摘の集約と提示

各ペルソナの指摘を統合し、重要度順に提示する。

> **レビュー結果（基本設計）— basic-design-reviewer**
> | # | 重要度 | 箇所 | 指摘 | 推奨対応 |
> |---|---|---|---|---|
> | 1 | 高 | §4.2 | 要件 R-007 が設計に未反映 | 設計へ追加 |
> …
> **所見**: 要件準拠は概ね良好。R-007 の反映後に次フェーズへ。

### 5. 対応のハンドオフ

- 指摘への対応要否は**ユーザーが判断**する（Human-in-the-Loop）。自動修正しない
- 対応する場合は該当スキル（`aide-dev-code` / `aide-brainstorm` / `aide-sync` 等）へ繋ぐ
- 監査オプション有効時は、レビュー実施記録を監査証跡に残す

## 注意事項

- ペルソナは**指摘に徹する**。実装・修正・判断はしない
- レビュー観点は `.aide/agents/` の定義に従う（フレームワーク提供・不可侵）。独自観点が必要な場合は `.claude/agents/` に独自エージェントを追加する（`aide-*` 既存ペルソナの上書きはしない）
- レビューは読み取り中心。対象を破壊的に変更しない
